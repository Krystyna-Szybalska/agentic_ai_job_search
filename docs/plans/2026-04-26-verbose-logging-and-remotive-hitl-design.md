# Verbose Logging, Remotive HITL & Report URL — Design

## Goals

Three related improvements for testing the Remotive job source:

1. **Verbose logging** — replace scattered `print()` calls with proper `logging`. Toggle via CLI flag. Use decorators to keep node code clean.
2. **HITL before Remotive API call** — pause the graph before fetching jobs, show the request, allow approve / reject / edit search query.
3. **Job offer URL in report** — markdown link in each entry of the generated report. Works for both `local` and `remotive` job sources (both have `url` field).

## Non-Goals

- Switching to `rich` or any third-party logging library (stdlib `logging` only).
- Editing `REMOTIVE_LIMIT` interactively (limit stays in `.env`).
- Restructuring tests around logging output.

## Approach

Single approach selected after evaluating alternatives:

- **HITL via `interrupt_before`** (consistent with existing `generate_report` pause), not raw `input()` inside the node.
- **`logging` (stdlib) + custom decorator** — no extra dependencies, idiomatic Python, teaches standard patterns.
- **`argparse`** for CLI — replaces manual `sys.argv` checking.
- **URL preserved end-to-end** through state — already happens by accident due to `dict(job)` propagation; no schema changes needed in vector store or normalizer.

## CLI

```
python main.py cv.pdf                        # default: INFO level
python main.py cv.pdf -v                     # DEBUG level (prompts, raw LLM responses)
python main.py cv.pdf -s "ML engineer"       # override REMOTIVE_SEARCH from .env
python main.py cv.pdf -v -s "AI engineer"    # both flags combined
```

Flags:

- `-v` / `--verbose` (flag, default off) — enables DEBUG logging

## Logging Configuration

```python
# utils/logging_config.py
import logging

_LOG_FORMAT = "%(asctime)s | %(levelname)-7s | %(name)s | %(message)s"
_DATE_FORMAT = "%H:%M:%S"


def setup_logging(verbose: bool = False) -> None:
    level = logging.DEBUG if verbose else logging.INFO
    logging.basicConfig(
        level=level,
        format=_LOG_FORMAT,
        datefmt=_DATE_FORMAT,
        force=True,
    )
    logging.getLogger("urllib3").setLevel(logging.WARNING)
    logging.getLogger("httpx").setLevel(logging.WARNING)
```

Each module obtains its own logger via `logger = logging.getLogger(__name__)` so messages are attributed to e.g. `agents.matching_agent`, `graph.nodes`.

### Granularity

| Level | What appears |
|---|---|
| INFO (default) | Node entry/exit (via decorator), key counts ("Found 20 jobs"), critic feedback summary |
| DEBUG (`-v`) | Per-job analysis logs ("Analyzing 3/20: ..."), full LLM prompts, raw LLM responses, Remotive request URL/params |

`urllib3` and `httpx` are silenced to WARNING to avoid spam from `requests`.

## Decorator

```python
# utils/decorators.py
import functools
import logging
import time


def log_step(name: str | None = None):
    def decorator(func):
        step_name = name or func.__name__

        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            logger = logging.getLogger(func.__module__)
            logger.info("→ %s started", step_name)
            start = time.perf_counter()
            try:
                result = func(*args, **kwargs)
                elapsed = time.perf_counter() - start
                logger.info("✓ %s finished (%.2fs)", step_name, elapsed)
                return result
            except Exception:
                elapsed = time.perf_counter() - start
                logger.exception("✗ %s failed (%.2fs)", step_name, elapsed)
                raise
        return wrapper
    return decorator
```

Resolves logger from `func.__module__` so logs are attributed to the calling module, not `utils.decorators`. Uses `functools.wraps` to preserve `__name__` (LangGraph reads it for node identification).

Applied to all node functions in `graph/nodes.py`:
```python
@log_step("Parse CV")
def parse_cv(state): ...

@log_step("Fetch jobs from Remotive")
def fetch_remote_jobs(state): ...
```

## HITL Before Remotive API

### Graph

`graph_builder.py` extends `interrupt_before` conditionally:

```python
interrupts = ["generate_report"]
if JOB_SOURCE == "remotive":
    interrupts.insert(0, "fetch_remote_jobs")

graph = builder.compile(checkpointer=checkpointer, interrupt_before=interrupts)
```

### State

`JobSearchState` gets one new field:

```python
class JobSearchState(TypedDict):
    cv_path: str
    cv_text: str
    cv_embedding: list
    retrieved_jobs: list
    matched_jobs: list
    critic_feedback: str
    validated_jobs: list
    report_path: str
    remotive_search: str  # NEW — replaces global REMOTIVE_SEARCH for runtime mutability
```

In `main.py`, initialized from CLI flag or fallback to settings:
```python
remotive_search = args.search or REMOTIVE_SEARCH
initial_state = {..., "remotive_search": remotive_search}
```

In `fetch_remote_jobs` node:
```python
def fetch_remote_jobs(state):
    jobs = fetch_remotive_jobs(state["remotive_search"], limit=REMOTIVE_LIMIT)
    return {"retrieved_jobs": jobs}
```

### Main Loop Logic

`main.py` distinguishes interrupt points by inspecting `state.next`:

```python
while True:
    state = graph.get_state(config)
    if not state.next:
        break  # graph done

    if state.next == ("fetch_remote_jobs",):
        handle_remotive_confirmation(graph, state, config)
    elif state.next == ("generate_report",):
        handle_results_review(graph, state, config)  # existing behavior
```

### Confirmation UX

```
=================================================
Ready to fetch jobs from Remotive API
=================================================
URL:    https://remotive.com/api/remote-jobs
Search: "python developer"
Limit:  20

Approve and fetch? (yes / no / type new search query):
> AI engineer

Updated search query.
Search: "AI engineer"
Approve and fetch? (yes / no / type new search query):
> yes
```

Logic:
- `yes` → `graph.invoke(None, config)` to resume, exit loop iteration
- `no` → `sys.exit(0)`
- anything else → treat as new search query, `graph.update_state(config, {"remotive_search": new})`, re-prompt

`print()` is used here (not logger) — this is **interactive UI**, not diagnostics.

## Print vs Logger Policy

- **Logger**: diagnostic output for developers (timestamps, levels, source module). Used in nodes, agents, tools.
- **`print()`**: user-facing UI — `display_results`, confirmation prompts, the Remotive preview panel. Stays in `main.py`.

This preserves Unix philosophy: stdout = data/UI, stderr (where logger goes by default) = diagnostics.

## Report URL

In `utils/report_generator.py`, after the location/salary line per job:

```python
url = job.get("url") or job.get("externalApplyLink", "")
if url:
    lines.append(f"[→ See the offer]({url})")
```

- Empty URL → line skipped (no ugly N/A)
- `externalApplyLink` is a fallback for local dataset entries that lack `url`
- Remotive path uses only `url` — the fallback never triggers but doesn't hurt

## Testing

- **`utils/decorators.py`** — pytest with `caplog` fixture: verify `@log_step` emits start/finish logs at INFO, propagates return value, propagates exception with `logger.exception`.
- **`utils/logging_config.py`** — single test: `setup_logging(verbose=True)` results in root logger at DEBUG.
- **HITL Remotive in `main.py`** — `monkeypatch.setattr("builtins.input", ...)` to simulate yes/no/edit flows. Mock the Remotive HTTP call.
- **`utils/report_generator.py`** — extend existing test (or add) to assert markdown link is present when `url` is set, absent when both URL fields missing.
- **No tests** for: print → logger migration in nodes/agents (effectively side effects of diagnostics).
